# Direct NVIDIA DLSS-G alpha (offscreen replay)
Uses the pinned official NVIDIA NGX D3D12 DLSSG helpers, not Optical Flow-only interpolation or a fake generated Present. No vendor runtime is shipped. Supply the official, compatible nvngx_dlssg.dll in RUNTIME_DIR; do not rename a different DLL. Use an isolated directory, overlays off, hardware GPU scheduling on, up-to-date drivers. The tool selects the NVIDIA adapter with largest dedicated VRAM, logs its identity, checks reported FrameGeneration availability, and creates a separate D3D12 device/queue. It never attaches to FH2. Every submitted private list completes by an actual fence before resource reuse or readback. Failure/timeout cannot alter native game output. A driver hang is still possible with an experimental backend.
 
## 1. Synthetic GPU smoke test
    azimuth_fg_replay.exe smoke "D:\FG-runtime" "D:\fg-smoke-new"
Two 1280x720 synthetic frames contain a moving textured foreground rectangle, actual projected depth, normalized current-to-previous UV motion, and known stationary camera constants. The first is a reset. The second calls the actual NGX frame generation API with one interpolated frame requested. Inspect the original pair and interpolated raw, GPU completion and disable-interpolation byte. Exit 0 = distinct second-frame candidate and flag 0, exit 2 = completed but not a candidate, exit 1 = error, exit 3 = private GPU fence failure. Distinct pixels do not prove correct interpolation.

## 2. Actual FH2 input
With the game closed between runs, use PR10 artifact Start-DebugCapture.ps1 -AutoTest -InstallProxy -ProxyMode ReShade -VisibleHDR -HDRLive -ProducerGpuWait -RenderSize auto -Output 3840x1600 -Quality quality -HUD delta -FGInputProbe -NoJitter -VisibleSeconds 10 -ReadyFile <unique> -WaitSeconds 300. Disable NR for first run; repeat with NR later. SDR uses -VisibleSR without HDR. No marker. Verify the two selected resolves are consecutive, fresh, non-reset on the second, jitter off, both FG INPUT_FINAL final=1 hudless=1, saved with GPU fence and exact matching RAW dimensions. Do not run if capture incomplete or camera cut. Use separate process after game exit. Example with observed 2592x1080 input, first resolve 441:
    azimuth_fg_replay.exe replay "D:\FG-runtime" "D:\capture\gpu-raw" "D:\fg-hdr-new" 441 2592 1080 3840 1600 1 0 1 1 probe-no-camera
The final argument explicitly permits a diagnostic without proven camera matrices; the actual SDK may reject it. No identity matrices are invented for FH2. Depth inversion, MV normalization scale are operator-declared; defaults in example reflect prior SR metadata, not independently proven FG semantics. Capture final targets are display-domain candidates, not actual present lineage. Do not interpret HDR packed RGB10 as SDR.

Alternatively supply a verified camera file instead of probe-no-camera. ASCII whitespace format: FGCAM1 then exactly two records, each starts with the actual resolve ID, followed by 5 row-major matrices of 16 finite floats (view-to-clip, clip-to-view, clip-to-lens-clip, current-clip-to-previous-clip, previous-clip-to-current-clip; no jitter), pinhole offset 2, position 3, up 3, right 3, forward 3, near/far/vertical FOV radians/aspect 4. Values must be measured and verified for that exact frame. No raw CB row names alone prove this. The tool does not certify supplied camera matrices.

## 3. Evaluation and limits
NGX CreateFeature FrameGeneration and EvaluateFeature are executed using separate private R10G10B10A2 display-domain backbuffer and HUD-less, R32_FLOAT depth, R16G16_FLOAT motion, output texture and four-byte disable-interpolation hint buffer. First reset output is diagnostic. Second output is a candidate only if fence completes, SDK writes disable byte zero, and output differs from sentinel and both source frames. No actual Swapchain present, Reflex, frame pacing, or 2x in-game output. Do not conflate direct NGX success with supported Streamline integration. This is a technical experiment; runtime capability and correct image depend on NVIDIA runtime and actual input semantics. Next step: prove actual presentation lineage, verified camera and reset contract, then safe single-owner insertion (or supported Streamline proxy) with pacing and resize handling.
