# FH2 SR play beta (fixed profile, explicit opt-in)

Install dxgi.dll and azimuth_ngx.dll next to azimuth.exe and supply an official compatible nvngx_dlss.dll. Copy azimuth_sr.ini beside azimuth.exe, set Enabled=1 and set actual Render and Output dimensions, Quality (quality/balanced/performance), HDR (0/1), Jitter (1/0), and Preset (default/J/K/L/M). Restart after edits. Explicit AZIMUTH_SR_MODE=preview/debug/dlaa takes precedence. An unset or disabled sidecar preserves previous behavior (including legacy debug sidecar). AZIMUTH_SR_MODE=play explicitly selects sidecar settings. Do not confuse this with engine resolution control: choose actual scene resolution in Azimuth, turn native AA off, and set game/display HDR yourself. Exact game passes and NGX optimal range must match. Previous evidence covers 1080p SDR and 3840x1600 HDR; other combinations are experimental.

Play starts after the observed full native scene chain and fresh SR warmup; no keys, RAW dumps, automatic exit, or duration limit. The existing GPU producer dependency and rendering gates are unchanged. Only ResizeBuffers/ResizeBuffers1/SetColorSpace1 guards are installed, not Present/Present1. Restart if a swapchain is created/resized or color space changed after activation. No guarantee of menu/photo/loading classification. Native fallback retains native draws, with a history reset requested after retired unrouted groups or busy slots. Already recorded fallback may contain jitter. Metadata exhaustion, NGX failure, or unavailable guard disables play until restart. Do not use RenderDoc with play mode.

One immutable private SR snapshot per live slot is reused only after successful recording retirement and all batch fences have completed. Ambiguous batches remain quarantined. Remaining replay surfaces and descriptor heaps are allocated as before. SR PLAY_STATS every five seconds reports attempts, recorded, GPU complete, native retired, busy slots, snapshot reuse, live slots and failed batches. This is not FPS or scan-out proof. Initial per-resolve logs are sampled; use bounded diagnostics for complete capture.

No FG, no runtime hot switching, no claim of visual quality or performance without game tests.

For a bounded regression run use Start-DebugCapture.ps1 with -AutoTest -VisibleSR or -VisibleHDR -HDRLive, -RenderSize WxH, -Output WxH, -Quality quality/balanced/performance, -Preset default/J/K/L/M, -ProducerGpuWait and optional -NoJitter. The actual game dimensions must match. The existing measured profiles also work without -RenderSize. The launcher explicitly selects preview and restores its process environment; it does not test continuous play. Test play by launching normally with the sidecar and externally closing the game after the intended run.

## Automatic scene profile (experimental)
Render=auto (also default if omitted) waits for three eligible matching scene/depth/MV/resolve sizes and validates the actual NGX range. Exact native PSO descriptions are retained with owned shader bytecode, root references and input semantics until the size is accepted. Output remains explicitly configured and must match the native final pass. Quality=auto queries Quality/Balanced/Performance/UltraPerformance, excludes unsupported ranges and picks nearest runtime optimum. Quality=ultraperformance is explicit. Fixed quality never silently changes. 1728x720 -> 3840x1600 Performance must reject if runtime min is 1920x800; automatic quality may also reject. No engine resolution override or hot reconfiguration.

## NR guide and HUD experiments
HUD=native remains the default. HUD=delta estimates a lower bound for premultiplied UI alpha independently at the four native texels and composites onto the high-resolution SR background. HDR t2 becomes the clean SR postfx scene; native final curve/levels are preserved. This assumes normalized premultiplied source-over; it is not true alpha recovery or independent high-resolution UI rendering, can under-estimate opaque elements, and is experimental. Revert to native if halos or HDR shifts appear. Native HUD draws often use depth, so do not bypass their occlusion tests.
DepthInverted, MVJittered, MVScaleX/Y (multipliers of render dimensions), PreExposure and ExposureScale allow deliberate calibration comparisons through the actual NGX creation/evaluate parameters. AutoExposure remains enabled; scalar values are not extracted game exposure. Defaults retain previous behavior. NR INPUT_EVALUATE reports actual proxy call arguments and return, not evidence that external NR hooked or consumed the call. A >500 ms evaluation gap requests history reset. Launcher options mirror these settings. Verify semantics with raw captures before changing defaults.

### Bounded NR guide extraction
Use -NRGuideProbe with AutoTest or Preview (not Play). For up to four exact FH2 non-indexed velocity triangle passes, two private R32_FLOAT outputs are rendered with the same native root bindings: full-size stencil (negative = -(stencil+1) when reprojection inputs invalid), and 64x1 guidecb (selected b1 rows). Only an identical resolve, MV sequence, command list and recording ID may enter the existing fence-protected RAW group; otherwise skip. No new NGX input tag, no fake object label or exposure. Native replay RAW is omitted for budget. Analyze with python tools/analyze_nr_guides.py <capture-folder> --output nr-guides.json. Compare daylight/tunnel, static and moving vehicles; reflected but unused b1 exposure/camera fields may not be meaningful. Depth clear observation is a candidate, not proof of reversed-Z. Keep defaults until actual evidence.

## Texture LOD experiment
LodBias=off is default. Explicit additive offset -2.5..0 is accepted, or auto with an explicit fixed Render and Output. Auto uses log2(renderWidth/outputWidth)-1 (bounded at -2.5), based on NVIDIA DLSS Programming Guide section 3.5. For 2592x1080 -> 3840x1600 the offset is about -1.567; start with -0.5 and -1.0 for controlled comparison. Render=auto with LodBias=auto disables bias because descriptors may be created before the scene profile is latched. The hook modifies only dynamic CreateSampler on the selected device when called directly by azimuth.exe and the sampler is anisotropic (>=4), wraps U/V, has MinLOD=0 and MaxLOD>=2. Static samplers, other entry points and DLL callers are untouched. This is a conservative candidate filter, not guaranteed world-only; descriptor reuse can affect other passes. ReShade may result in zero eligible calls. LOD SAMPLER / LOD PROFILE record actual changes. Existing descriptors cannot be restored when SR falls back; restart with off to restore native sampling. No claim of texture improvement until matched-motion visual/perf comparison; look for moire, foliage shimmer and VRAM cost. Debug launcher -LodBias supports the same values.

## Two-resolve motion validation
-NRTemporalProbe implies -NRGuideProbe and requires live VisibleSR (HDR requires -HDRLive). Selects the first two eligible resolves even on wide profiles; records only the core color/depth/MV/SR and optional stencil/guidecb, omitting postFX readbacks to stay within 256 MiB. This is a bounded diagnostic, not a new NR mask input. Verify adjacent Resolve IDs, fresh motion, reset and jitter in the trace. The visible route continues using the existing gates. The FH2 MV shader now zeros non-finite, out-of-range stencil/reprojection or FP16-overflow vectors rather than emitting invalid values; valid finite vectors are unchanged. A zero fallback does not imply a correct vector or NR confidence mask.

The existing tools/analyze_nr_guides.py now emits temporal_pairs for adjacent captured resolves. Decodes scene R11G11B10_FLOAT and compares bilinear current-to-previous warps using zero / default / reversed / half / double normalized MV, on the same valid sample set, with optional stencil-group and raw depth-difference summaries. Log-luma residual and median-centered residual are diagnostics, not actual motion ground truth; check fresh MV, reset, jitter and NR domain. A current color readback after NGX evaluate could already be altered by an external NR implementation. Raw nonlinear depth delta is not a disocclusion mask. Test with SR-only first, then NR. The analyzer never changes the game or automatically chooses parameters.
